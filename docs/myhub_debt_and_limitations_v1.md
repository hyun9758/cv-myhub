# MyHub — 이번 실습에서 만들어진 빚(Debt) v1

> Day 1 정적 CV 사이트(`myhub_01_static`) 구현 과정을 되짚어, 프롬프팅 방식의 한계와 결과물(정적 웹 페이지) 자체의 한계를 정리합니다. Day 2 풀스택 전환의 출발점(baseline) 역할을 합니다.

## 1. 프롬프팅 방식이 남긴 빚

### (1) 모호한 요구사항이 있었다
- "무채색 계열 + 단일 액센트 컬러"에서 정확한 HEX 값(`#3b5bdb`)은 구현 단계에서 임의로 확정됨 — 사전에 합의된 값이 아니었음
- "가상 데이터를 그럴듯하게" 대신 이번엔 실제 포트폴리오 데이터를 받아 대체했지만, 프로필 사진은 여전히 이니셜 아바타(SVG)로 대체 — 실사진 부재를 "그럴듯하게" 땜질한 것과 본질은 동일

### (2) 요구사항 완전성/정확성 검증 단계가 없었다
- PRD(§5)는 구현 이후 역산되었고, 구현 전 "이 요구사항 집합이 완전한가"를 묻는 리뷰 단계는 없었음
- 3.6에서 추가한 `links[]`, Open Graph도 사후에 떠오른 개선안이지, 사전 스펙 리뷰로 걸러진 것이 아님

### (3) 질문 없이 끝까지 진행했다
- 각 단계 사이에 사용자 확인을 받긴 했으나(AskUserQuestion), 개별 UI 디테일(엔트리 레이아웃, 칩 스타일 등)은 별도 확인 없이 구현자가 임의로 결정

### (4) 추적 불가능성
- `data.json`의 각 필드 변경이 어떤 요구사항 ID(TR/DR/UR/FR)에서 비롯됐는지 연결하는 장치가 없음. PRD의 ID 체계는 사후에 붙인 라벨일 뿐, 구현 커밋과 1:1로 연결되어 있지 않음

### (5) 체계적 인수 기준이 없다
- "정상적으로 렌더링된다"의 기준이 코드 작성자(에이전트 겸 본인)의 주관적 판단에 의존. 자동화된 인수 테스트 없음

### (6) 우선순위/충돌 해소 규칙이 없다
- "외부 라이브러리 금지" vs "Google Fonts(Noto Sans KR) 로드"는 실질적으로 외부 리소스 의존이라는 점에서 긴장 관계이나, 별도 논의 없이 구현자가 조용히 절충함

## 2. 현재 MyHub(정적 사이트)의 한계

### 2.1. 완화 가능한 한계
| 한계 | 현재 상태 |
|---|---|
| 콘텐츠 수정이 곧 "코드 작업" | `data.json`의 JSON 문법 오류 시 스키마 검증기 없이 렌더링이 조용히 깨짐 |
| 반영 시차 | 텍스트 하나 고치려면 git add/commit/push → Pages 빌드(수십 초~수 분) 필요 |
| 버전 관리가 Git 지식에 의존 | 커밋 히스토리로만 롤백 가능, UI 상 되돌리기 기능 없음 |
| 동시 편집 불가 | 두 명이 동시에 `data.json`을 고치면 merge conflict를 손으로 풀어야 함 |
| 파일 기반 관리의 한계 | 검색·정렬·유효성 검사 기능 없음, 로컬 확인에 `python -m http.server` 필요 |

### 2.2. 구조적으로 해결 불가능한 한계 (서버가 없어서)
- 인증/권한 관리 불가 (비밀번호 검증을 서버에서 할 수 없음)
- 변경사항의 영속적 저장 불가 (새로고침하면 `data.json` 원본으로 복귀)
- 민감 로직/시크릿이 필요한 기능 전부 불가 (문의 폼 전송, API 키 연동 등)
- 접근 제어 기반 콘텐츠 분기 불가 ("로그인한 사람에게만 보여주기" 등)
- 서버 로그 기반 방문자 분석/모니터링 불가 (GitHub Pages는 자체 로그 미제공)

## 3. Day 2로 넘겨줄 결핍 목록

1. **요구사항 사전 정제(Grilling)** — 유저스토리 + 인수기준으로 재구성, 완료 기준을 검증 가능한 문장으로 명문화
2. **데이터 스키마 사전 확정** — 서술형이 아닌 정식 스키마(필드명·타입·필수여부)로 구현보다 먼저 확정
3. **공통 레이아웃 사전 설계** — 와이어프레임 수준의 참조 자산 확보
4. **영속 저장/인증/서버 로직을 위한 풀스택 아키텍처** — B/E + F/E + DBMS
5. **구현 규칙을 강제하는 하네스(서브에이전트/훅)** — 프롬프트 수준이 아닌 물리적 강제 장치
6. **자동화된 인수 테스트** — 사람이 아닌 도구가 "완료"를 판정
